# Phase 6: what is integrated, and what is still unported

This branch (`feat/rust-phase6`) is the INTEGRATION step only. It contains phases 2, 3a, 3b,
4 and 5 merged and building. None of the remaining phase 6 scope below has been started.

## Integrated

- Phase 4 (OSC, MIDI input, lights, ProPresenter: PR #240), phase 3b (Playback: #241) and
  phase 5 (Planning Center: #242) on top of phase 2 (#239).
- One `Runtime` builder, `Runtime::with_all(settings, auth, playback_options, pco_options,
  output_backends)`. `new`, `with_playback_options`, `with_pco`, `with_options` and
  `with_backends` all delegate to it. Plugins register in the health order Python reports:
  lights, demo/Planning Center, the Playback input (the real MIDI plugin when the MIDI source
  is real, otherwise the Playback plugin), then ProPresenter.
- The server no longer contains any stubbed integration route.
- Contract: one `contract/transcripts.json` with `steps` (103, includes Playback), `pco_steps`
  (96) and `output_steps` (75). `contract.py replay --profile pco|outputs`. Both
  `run_baseline.sh` and `run_rust.sh` run all three profiles (ports PORT, +100 pco, +200 pco
  mock, +300 outputs, +400 ProPresenter mock). Uuid normalisation covers `id`, `event_id`
  and `cue_id`.
- The `rust.yml` branch filter lists phase 4 and phase 6.

# Phase 4: MIDI input, lights and ProPresenter

Rust ports of the `midi_playback`, `lights` and `propresenter` plugins and the OSC output, wired
into `stagepilot-server` in place of the phase 2 stubs.

## Crates

- `stagepilot-osc`: `OutputError` (public vs internal, like Python's ValueError/RuntimeError),
  `OscBackend`/`OscOutput`, UDP backend, in-memory fake. Encoding uses `rosc`; byte parity with
  python-osc is proven by `tests/fixtures/osc_golden.json` (67 packets), generated by
  `tools/rust-output/gen_osc_golden.py` through the real Python UDP backend. CI regenerates it
  and fails on a diff. python-osc sends int64 (`h`) once `bit_length() > 31` (so also -2**31).
- `stagepilot-midi`: `MidiPlaybackPlugin`, backends and `fake`. Real hardware (`midir`) is behind
  the non-default feature `midir-backend`.
- `stagepilot-lights`: `LightsPlugin` (OSC and MIDI methods). Only the saved method fires; OSC cues
  are one-shot UDP, MIDI cues short note pulses. Nothing is sent unless a cue or test asks.
- `stagepilot-propresenter`: plain-HTTP `reqwest` client (no TLS, `default-features = false`),
  plugin, snapshot types.

## Server

`outputs.rs` builds the plugins from the resolved settings and keeps registration (health) order:
lights, services, Playback input (`midi_playback` when MIDI is real, otherwise the placeholder),
ProPresenter. `routes_outputs.rs` serves `/api/v1/midi/*`, `/propresenter*`, `/lights*`.
`PUT /settings` follows the Presentation and MIDI changes live (409 while the timer runs).
The Playback arbiter is still phase 3: with MIDI selected the actions go straight to the state
service, as Python's arbiter does with no Playback API connected.

## Why `midir-backend` is optional

The Linux CI runner has no `libasound2-dev`/`pkg-config` and nothing is installed there.
Linux therefore tests all behaviour through fakes; Windows and both macOS runners build and test
with `--features stagepilot-midi/midir-backend,stagepilot-server/midir-backend`. See
`linux-midi.md`. The feature was not compiled locally (no ALSA here); CI on the hosted runners is
its first build.

## Contract

`scripts/contract` gained an "outputs" profile (75 steps): fake MIDI ports, a deterministic mock
ProPresenter (`mock_propresenter.py`; the requests each side makes are compared too) and OSC to a
dead loopback port. `run_baseline.sh` and `run_rust.sh` replay it against Python and Rust; both
pass 75/75 (and 56/56 for the original profile). Rust uses `--contract-outputs`.

Test mapping: `phase4-test-map.md`.
